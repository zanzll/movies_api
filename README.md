Movies API

1. Краткое описание проекта

Movies API — учебный проект REST API для управления базой данных фильмов. Приложение позволяет добавлять, просматривать, изменять и удалять информацию о фильмах.

2. Основные возможности приложения

- Добавление новых фильмов.
- Получение списка фильмов.
- Поиск фильма по ID.
- Полное и частичное обновление информации.
- Удаление фильмов.
- Проверка и валидация данных.
- Работа с базой данных SQLite.
- Асинхронная работа с базой данных.

3. Технологический стек

- Python — язык программирования.
- FastAPI — создание REST API.
- Pydantic — проверка и валидация данных.
- SQLAlchemy 2.0 — работа с базой данных.
- SQLite — база данных.
- aiosqlite — асинхронный драйвер SQLite.
- Alembic — миграции базы данных.
- Uvicorn — запуск приложения.

5. Быстрый старт

5.1. Клонирование репозитория

git clone https://github.com/zanzi/movies_api.git
cd movies_api

5.2. Установка Python и зависимостей

Установить Python, затем выполнить:

pip install -r requirements.txt

5.3. Применение миграций

alembic upgrade head

5.4. Запуск приложения через Uvicorn

uvicorn src.main:app --reload

После запуска документация API доступна по адресу:

http://127.0.0.1:8000/docs

6. Основные эндпоинты

Метод| Путь| Описание
GET| "/"| Проверка работы API
GET| "/movies/"| Получение списка фильмов

7. Фильтрация и сортировка

В доступном описании проекта фильтрация и сортировка не указаны. Их наличие необходимо проверить в реализации API перед добавлением описания.

8. Модель данных

Каждый фильм содержит следующие поля:

- "id" — уникальный идентификатор.
- "title" — название фильма.
- "genre" — жанр.
- "rating" — рейтинг от 0 до 10.
- "year" — год выпуска.

9. Ограничения базы данных и валидация

При добавлении фильма проверяются следующие условия:

- Название должно содержать от 2 до 200 символов.
- Жанр должен содержать от 2 до 100 символов.
- Рейтинг должен находиться в диапазоне от 0 до 10.
- Год выпуска должен быть не меньше 1888 и не больше текущего года.

Для хранения информации используется SQLite. Работа с базой данных осуществляется асинхронно с помощью SQLAlchemy и aiosqlite.

Для управления изменениями структуры базы данных используется Alembic.
